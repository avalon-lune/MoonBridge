# 本地存储与迁移

## 建议布局

把文件放在自己确认不参与云同步的目录，例如家目录下自建的 Local Games：

```text
~/Local Games/
├── MoonBridge/     # 项目、App、Runtime、Library
├── Archive/        # 下载的原始包，或尚待导入的完整游戏文件夹
└── Backups/        # 自行创建的迁移副本、存档快照
```

Archive、Backups 是建议的用户目录，不是启动器自动接管的下载区或云备份服务。桌面、文稿及其他位置是否同步，由 iCloud 和其他同步工具的实际配置决定；月渡不会替你修改这些设置。

## 原压缩包与导入副本

导入成功后，游戏资源位于 `MoonBridge/Library/Games/<游戏ID>/content`。游戏库记录选定 EXE，运行时从该副本读取。原下载包不再是运行所必需，但仍可保留作重新导入的来源。

原下载包、已解压待导入目录、已导入副本可能同时占用空间。删除 Archive 的原包不会自动删除 Library；反之，也不能从 GitHub 源码仓库找回个人游戏与存档。

`.xp3`、`.bin`、`.dat` 等可能是游戏必须的资源，不应因外观像压缩文件就删除。先在游戏详情中“打开游戏文件”确认实际使用位置。

## 存档与快照

游戏决定实际存档路径。备份应覆盖游戏目录和相应 Wine 前缀；月渡的“存档环境”入口不是承诺所有游戏都采用统一存档目录。

`Library/Backups` 主要保存文件覆盖补丁前的原文件，不是每次存档自动快照。家目录同级 Backups 是另外组织的手动备份。恢复旧快照前，另存最新进度，避免倒退。

## 整体移动项目

先在游戏内保存并退出，再将整个 MoonBridge 目录复制到目标位置，核对复制结果。保持 App、Runtime、Library 的同级关系，然后从新位置打开 App，验证实际游戏、旧存档以及新存读档。确认新位置可用后再处理旧副本。

0.1.1 会在启动前修复旧的绝对 G: 链接，并改用相对映射；目录名称含空格的迁移已有回归检查。整体迁移不意味着自动清理 iCloud 上的旧副本；云端删除应由用户明确选择。

## 源码仓库

Git 忽略 Runtime、Library、构建缓存、私人诊断与测试存档。仓库保存源代码和运行库恢复方法，不能替代个人数据备份。
