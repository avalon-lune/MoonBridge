# 游戏资料与 AI 助手 / 0.2.0

月渡的游戏启动与 AI 助手分别运行。Wine、主程序选择、汉化修复及既有存档位置沿用原方案。

## 使用

1. 打开侧栏 **AI 设置**，开启功能，填写 HTTPS API 基础地址和 API Key，保存后可刷新接口模型列表，从列表选择模型或手动输入，保存后测试连接。默认是 OpenAI Responses API 与 `gpt-6.1-terra`，推理强度 medium。已有 Key 可以在多个自用软件中使用，各次调用计入其所属账户的额度。
2. 需要代理时填写本机地址，例如 `http://127.0.0.1:7897`；不要使用仅 Docker 容器可解析的 `host.docker.internal`。更换端口时以实际配置为准。
3. 导入游戏后可按开关自动打开资料匹配，也可以从已有游戏的主页点击 **匹配资料**。查询可使用中文名、日文原名或英文名。
4. 对照作品名、来源与发行信息选择候选，再保存。没有找到时可以改词重搜或手动编辑；匹配不会改变实际游戏标题、EXE、补丁或区域配置。
5. 主页的 **和千咲聊聊** 使用所有游戏共用的聊天和长期记忆。历史默认折叠，新一轮单独展示；默认不允许剧透，可取消回答。清空共享聊天会影响所有游戏页面，但保留长期事项。
6. **运行设置** 仍能选择原主程序、语言、虚拟桌面、补丁、验证清单和日志。

仅检索作品资料无需模型 Key。选定来源后，若已配置模型，月渡会依据来源事实独立组织中文概况，保留原文并标记整理来源；请求失败时提示概况待整理，来源原文在折叠区查看。也可点击“整理中文概况”重试。缺少依据时应说明不确定，不会抽取整个游戏脚本或自动读取进度。

## 数据在哪里

```text
Library/Companion/
  settings.json          # 开关、API 地址、模型、代理，不含密钥
  metadata/<游戏ID>.json  # 用户选中的资料、来源、封面相对路径
  covers/                # 本地封面缓存
  memory.sqlite          # 所有游戏共用的聊天、检索索引与长期事项
  chat/<游戏ID>.json      # 旧版记录，迁移后仍保留原文件
```

原 `Library/library.json` 数据结构保持 v1；不为增加 AI 字段迁移游戏库。共享记忆使用系统 SQLite，不下载数据库组件。旧版各游戏聊天事务合并、按消息 ID 去重，原文件不删除。下载封面和问答均不写入 `Games` 或 `Prefixes`。备份整个项目时包含 Companion 目录即可保留上述资料。API Key 属于本机 macOS 钥匙串，使用设备限定的凭据项，不随项目目录或 GitHub 仓库发布。

API 地址规范化后分别对应钥匙串凭据。仅修改地址不会把旧地址的 Key 自动发到新服务。设置页空白 Key 表示保留该地址已存的凭据。测试连接会产生一次小额模型调用。此版本使用本地 ad-hoc 签名，重建后 macOS 可能重新询问钥匙串访问权限。

## 何时联网、发送什么

| 操作 | 发送内容 | 目标 |
| --- | --- | --- |
| 搜索作品 | 清理过的检索名称 | VNDB、Bangumi |
| 保存候选 | 选中的作品 ID，以及下载封面请求 | 对应资料站与受支持图片 CDN |
| 中文整理 | 选中资料的作品名、来源简介 | 设置中的 API 服务 |
| 游戏问答 | 当前作品名、已选简介、开发商、来源、问题、有限近期对话、相关旧消息片段与长期事项 | 设置中的 API 服务；开启搜索时由其执行联网检索 |
| 测试连接 | 短连接测试提示 | 设置中的 API 服务 |

这些请求不携带游戏文件、存档、Wine 日志或自动扫描到的本地资源路径。只在主动问答时提交相关记忆，不上传整个 SQLite 文件。API 使用 `store:false`，不依靠提供商托管对话；该参数不等同于提供商不进行任何必要的请求处理或留存。实际服务规则以所选 API 提供商为准。

关闭 AI 功能会停用资料联网与新的模型请求。已缓存资料仍可查看，正常导入、运行游戏和存读档继续可用。程序没有上传整个游戏包的接口，没有后台批量资料同步。

## 来源与实现边界

- [VNDB Kana 官方 API](https://api.vndb.org/kana)：公开作品资料、真实封面、开发商和非剧透标签；遵守其非商业使用及数据许可条款。
- [Bangumi 官方 API](https://bangumi.github.io/api/)：中文标题、作品简介及封面补充；显示对应条目的来源链接。
- [OpenAI 模型列表接口](https://developers.openai.com/api/reference/resources/models/methods/list)：根据当前 API 与 Key 获取模型 ID；模型列表不等于所有模型都支持问答和搜索。
- [OpenAI Responses 联网搜索](https://developers.openai.com/api/docs/guides/tools-web-search)：问答检索与可点击来源。
- [GPT-6.1 Terra 官方说明](https://developers.openai.com/api/docs/models/gpt-6.1-terra)：当前默认模型与推理参数。

封面由作品资料站提供，版权仍归原权利人。本仓库不打包用户下载的封面、游戏资源或聊天记录。候选、来源简介与 AI 生成的中文整理应区别看待。默认避免剧透是提示与来源过滤，不能保证互联网资料完全不含剧透。作品匹配和回答都需要用户判断，不能作为已验证游戏兼容性的证据。

## 回退

本次更新不变更游戏数据格式。关闭应用后恢复备份的旧 `.app` 与源码即可回退软件；现有 `Games`、`Prefixes` 和 `library.json` 不需要为回退移动。独立 Companion 资料可保留，旧版本会忽略它。

## 千咲与共享长期记忆

千咲是月渡游戏库管理员，使用核对过的《鸣潮》角色外貌与手绘 Q 版头像。完整设定、官方事实与月渡定制部分见 [角色说明](CHISA_PERSONA.md)。

每条新消息和回答都会写入共享 SQLite。跨游戏保留同一段近期对话，旧对话通过本地全文检索与中文词组相关排序按需召回；不是把所有历史直接塞进每轮请求，也不是在本机训练模型。

使用“请记住：……”或记忆面板保存明确事项；以“以后叫我”“我喜欢”等开头的简短自述会作为偏好条目保留。长期事项带更新时间，当前明确纠正优先。可以查看、添加、删除事项，检索旧消息，或清空共享聊天。删除单条事项与清空聊天范围不同，旧聊天原文独立保留。

询问当前模型与推理强度时，月渡直接读取配置回答；普通回答由所选 API 模型生成。
